**1. Large, Monolithic Methods Reduce Readability and Maintainability**

Several methods in `TruffleFile` are quite lengthy and perform multiple, distinct steps, making them harder to understand, test, and maintain. For example:

  This method contains a non-trivial loop for reading the file into a dynamically resizing buffer, with multiple nested conditionals and error handling. The logic for buffer resizing, reading, and error cases is all inlined, making the method dense and difficult to follow at a glance.

  *Suggestion*:

**2. File Tree Traversal Logic is Deeply Nested and Hard to Follow**

- **`visit(FileVisitor<TruffleFile> visitor, int maxDepth, FileVisitOption... options)`**:

The logic for handling each event type, error propagation, and traversal control is all inlined.

  *Why it matters*:

  *Suggestion*:
