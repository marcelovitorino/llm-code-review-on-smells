This separation can make the code harder to maintain and extend, as changes to the tree structure or traversal logic require changes in multiple places.

**Suggestion:**  
Consider moving more tree-related behavior into the `Node` class itself, such as methods for finding parents, traversing children, or querying descendants. This would make `Node` a more responsible owner of its data and reduce the risk of it becoming a passive data holder manipulated externally. See Fowler's discussion on [Data Class](https://refactoring.com/catalog/dataClass.html) and the benefits of encapsulating behavior with data.

**Suggestion:**

**Suggestion:**
