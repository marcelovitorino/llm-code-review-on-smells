**1. The constructor is doing too much**

**Suggestion:**

- Extract event parsing for each log entry type into separate methods (e.g., `handleStateChange`, `handleNewElection`, `handleReceivedProposal`, `handleException`).
- Move the logic for updating leader/epoch state into dedicated methods.
- Consider extracting the main loop into a method like `parseLogEntries(LogIterator iter)`, so the constructor is only responsible for initialization and orchestration.

**2. The `Message` inner class is unused and incomplete**

**Suggestion:**

If the intent is for `JsonGenerator` to be a reusable parser, consider separating the parsing logic from the data holding. For example, a static `parse` method could return a data object, or the class could expose methods for accessing the parsed events and metadata.

If this class is to be used as a library, consider moving the CLI logic to a separate class.

---

Extracting responsibilities into smaller, well-named methods will greatly improve the maintainability and clarity of the code. Additionally, removing unused code (such as the `Message` class) and considering separation of concerns between parsing and data holding will further enhance the design.
