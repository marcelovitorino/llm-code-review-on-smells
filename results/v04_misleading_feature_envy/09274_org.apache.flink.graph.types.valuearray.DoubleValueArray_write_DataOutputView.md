**2. Iterator Statefulness and Reuse**

The class exposes a single instance of `ReadIterator` as its iterator, which is reset and reused on each call to `iterator()`. This means that only one iteration can be in progress at a time; concurrent or nested iterations will interfere with each other.

*Why it matters*: This design can lead to subtle bugs if a client expects to be able to iterate multiple times in parallel (e.g., nested loops or streams). While not strictly a code smell in the sense of method length or feature envy, it is a sign that the class is managing more state than necessary, and the iterator is more tightly coupled to the array than needed.

*Suggestion*: Consider returning a new `ReadIterator` instance on each call to `iterator()`, rather than reusing a single instance. This would make the class safer and more predictable for clients.

*Suggestion*: If there are common operations performed on the array (e.g., summing, filtering, or mapping values), consider adding them as methods to this class, to keep data and behavior together and reduce the risk of feature envy elsewhere.

*Suggestion*: Extract the element-wise comparison into a private method to improve clarity and maintainability.
